# Sync Handler

## Overview

- Lives in experiment layout.svelte.
- Persists across navigations.
- Handles async database operations (non-blocking for navigation).
- Uses client-side database client for non-validated submissions (e.g., survey responses).
- POSTs to server for validated submissions (e.g., graded questions); server then validates and
  submits with service role client.
- Sync record is kept in local storage.
- Sync record contains syncedAt (null = unsynced) and localStorageKey (key to sync object).
- Pages and components pass data to the sync handler

## Intended data boundaries

### Component - lowest level

- Creates inputs.
- Generates new data from inputs.
- Data is bound to and owned by parent.

### Page - owns component data

- Page owns data generated by components so that page can operate on data.
- Allows page to check for question completeness, pass data to syncHandler, etc.

### SyncHandler - highest level

- Receives records (key and data) from pages.
- By default, persists data to local storage using key.
- If wired to database, syncs data in background.
- Background operations allow user to navigate between pages without interrupting syncing.

## SyncHandler class

- Takes client-side supabase-js client in constructor
- Holds sync queue
- On instantiation, constructs queue from record book in local storage
- Enqueues new items upon request
- An enqueue request requires a key, a payload, and an optional operation from a predefined list
- Enqueuing saves to local storage first, then adds to the queue

## _database functions

- One database module per component that needs to save data
- Modules export { save, sync, validatedSync }
- save: Imported by page, passed to component as prop. Called when the component wants to save data;
  enqueues current state with syncHandler.
- sync: Imported by syncHandler. Shapes component state into database representation, then syncs to
  database.
- validatedSync: Imported by syncHandler. Shapes component state into database representation, then
  submits to server for validation + syncing.
